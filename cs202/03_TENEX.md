# TENEX：虚拟内存与分时系统的里程碑

**论文：** *TENEX, A Paged Time Sharing System for the PDP-10*
**作者：** Daniel G. Bobrow, Jerry D. Burchfiel, Daniel L. Murphy, Raymond S. Tomlinson
**机构：** Bolt Beranek and Newman (BBN), 1972
**发表于：** Communications of the ACM, Vol. 15, No. 3

---

## 一、论文背景与动机

1960 年代末到 1970 年代初，分时系统（time-sharing system）正在从实验室走向主流。MIT 的 CTSS 和 Multics 已经证明了分时的可行性和价值——让多个用户同时交互式地使用一台计算机，而不是排队等待批处理结果。然而，当时的分时系统要么过于复杂（如 Multics），要么功能有限。

与此同时，DEC 的 PDP-10 正在成为大学和研究机构最受欢迎的计算机之一。PDP-10 原生的操作系统是 DEC 提供的分时监控程序，但许多用户对其功能和性能并不满意。BBN（Bolt Beranek and Newman，也就是后来参与建造 ARPANET 的那家公司）决定为 PDP-10 开发一个更先进的分时操作系统。

TENEX 的设计动机有几个关键维度：

第一，**提供真正的虚拟内存**。PDP-10 原生并不支持硬件分页，BBN 为此专门设计了一个硬件附加模块——BBN Pager，为 PDP-10 增加了地址转换和页面保护功能。这使得 TENEX 可以实现 demand paging，让每个用户进程拥有比物理内存大得多的虚拟地址空间。

第二，**改善用户交互体验**。TENEX 的设计者们非常重视用户界面，他们希望创建一个对交互式用户友好的系统，包括智能的命令行补全、统一的文件命名等。

第三，**支持 ARPANET 连接**。BBN 作为 ARPANET 的核心承包商，自然希望 TENEX 能够良好地支持网络访问。TENEX 后来确实成为了早期 ARPANET 上最流行的操作系统之一。

## 二、核心设计与关键创新

### 虚拟内存与 Demand Paging

TENEX 最核心的技术贡献是在 PDP-10 上实现了完整的虚拟内存系统。每个进程拥有一个 256K word 的虚拟地址空间（PDP-10 的 word 是 36 位），通过页表映射到物理内存。页面大小为 512 words。

关键的创新在于 demand paging 的实现：页面只在被实际访问时才从磁盘加载到内存。当进程访问一个不在物理内存中的页面时，BBN Pager 硬件会产生一个 page fault，TENEX 的页面调度器随后将所需页面从磁盘读入内存。

TENEX 的页面替换算法值得关注。系统维护了一个全局的页面使用信息，采用类似"时钟算法"（clock algorithm）的策略来选择被替换的页面。系统还实现了页面共享——多个进程可以映射同一个物理页面，这对于共享库和 fork 操作非常重要。

### 映射文件（Mapped Files）

TENEX 引入了一个优雅的概念：将文件直接映射到进程的虚拟地址空间。进程可以通过普通的内存访问指令来读写文件内容，而不需要显式的 read/write 系统调用。文件的页面按需从磁盘加载，修改后的页面在适当时机写回磁盘。

这个概念后来在 BSD UNIX 的 mmap() 系统调用中得到了广泛应用，至今仍是现代操作系统的核心功能之一。

### 进程模型与 Fork

TENEX 的进程模型支持 fork 操作——创建一个当前进程的副本。结合虚拟内存的页面共享机制，fork 可以非常高效地实现：子进程最初与父进程共享所有页面，只有当某一方修改页面时才进行实际的复制（即 copy-on-write 的早期形态）。

### 用户界面创新

TENEX 在用户界面方面的创新同样值得一提。它引入了命令行的 Tab 补全功能（在 TENEX 中是 Escape 键触发）——用户输入命令或文件名的前几个字符，按 Escape 键，系统自动补全。如果有多个匹配项，系统会显示可能的选项。这个功能后来被 UNIX 的各种 shell 继承，成为了命令行交互的标准特性。

TENEX 还提供了统一的、层次化的文件命名系统，支持版本号——每次修改文件时自动创建新版本，用户可以访问文件的任何历史版本。

## 三、重要的技术细节

### BBN Pager 硬件

TENEX 的虚拟内存实现依赖于 BBN 自行设计的硬件分页单元。这个硬件模块插入 PDP-10 的处理器和内存之间，拦截所有内存访问请求，进行虚拟地址到物理地址的转换。

BBN Pager 支持多级页表、页面保护位（读/写/执行权限）和 page fault 中断。它还提供了一个 TLB（Translation Lookaside Buffer）来缓存最近使用的页表项，减少地址转换的开销。

这种"通过添加硬件来增强现有计算机功能"的做法在当时并不罕见，但 BBN Pager 的设计质量和 TENEX 对它的充分利用，使得这个组合成为了虚拟内存实现的典范。

### 调度器设计

TENEX 的 CPU 调度器采用了多级反馈队列（multi-level feedback queue）的变体。交互式进程（等待用户输入的进程）获得较高的优先级，以保证响应速度；计算密集型进程则被逐渐降低优先级。这种设计在分时系统中非常有效，因为它自动地偏向交互式工作负载，而不需要用户手动设置优先级。

### 密码系统的 Timing Attack 漏洞

TENEX 在计算机安全史上留下了一个著名的反面教材。系统的密码验证机制存在一个 timing attack（时序攻击）漏洞，这个漏洞的发现和利用方式极其巧妙：

TENEX 的密码验证是逐字符进行的——系统从左到右比较用户输入的密码和存储的正确密码，一旦发现不匹配的字符就立即返回失败。这意味着：如果第一个字符就错了，验证会很快失败；如果前几个字符都对了，验证会花更长时间。

攻击者利用了 TENEX 虚拟内存的 page fault 机制来放大这个时间差异。具体方法是：将密码字符串精心放置在两个虚拟页面的边界上，使得第 N 个字符恰好在第二个页面的开头。如果前 N-1 个字符都正确，系统在比较第 N 个字符时会触发一个 page fault（因为第二个页面不在内存中），这个 page fault 的延迟远大于正常的字符比较时间，因此很容易被检测到。

通过这种方法，攻击者可以逐字符地猜测密码：每次只需要尝试所有可能的字符（最多 128 次），而不是暴力枚举所有可能的密码组合。一个 8 字符的密码，暴力破解需要 128^8 次尝试，而 timing attack 只需要 128×8 = 1024 次。

这个漏洞后来成为了计算机安全课程中的经典案例，它深刻地说明了：**安全性不仅取决于算法的数学强度，还取决于实现的物理特性。** 现代密码学实现中普遍采用的"常量时间比较"（constant-time comparison）技术，其动机可以直接追溯到 TENEX 的这个教训。

## 四、优缺点分析

### 优点

1. **虚拟内存的完整实现。** TENEX 展示了 demand paging 在实际系统中的可行性和价值，为后来的操作系统提供了重要参考。
2. **优秀的用户体验。** 命令补全、文件版本控制等功能在当时极为先进，显著提升了交互式计算的效率。
3. **网络支持。** 作为早期 ARPANET 的主要操作系统之一，TENEX 为网络计算的发展做出了重要贡献。
4. **映射文件的概念。** 将文件映射到虚拟地址空间的思想影响深远，至今仍是操作系统的核心功能。

### 缺点

1. **硬件依赖性强。** TENEX 依赖于 BBN 定制的分页硬件，这限制了它的可移植性和普及范围。
2. **安全设计不足。** 密码验证的 timing attack 漏洞暴露了系统在安全设计上的考虑不够周全。
3. **与 DEC 官方系统的竞争。** DEC 后来推出了自己的分页分时系统 TOPS-20（实际上大量借鉴了 TENEX），TENEX 作为第三方系统逐渐被边缘化。
4. **PDP-10 平台的局限。** 随着 PDP-10 架构的衰落，TENEX 也随之退出了历史舞台。

## 五、历史影响与后续发展

TENEX 的直接后继是 DEC 的 TOPS-20 操作系统。DEC 在 1976 年收购了 TENEX 的技术，并在其基础上开发了 TOPS-20，成为 PDP-10 系列后期的标准操作系统。TOPS-20 继承了 TENEX 的大部分设计，包括虚拟内存、命令补全和文件版本控制。

TENEX 对 UNIX 世界的影响同样深远。BSD UNIX 中的虚拟内存实现（特别是 4.2BSD 和 4.3BSD）在概念上与 TENEX 有诸多相似之处。mmap() 系统调用直接继承了 TENEX 映射文件的思想。UNIX shell 中的 Tab 补全功能（最早出现在 tcsh 中——"t"代表 TENEX）更是对 TENEX 用户界面创新的直接致敬。

在安全领域，TENEX 的 timing attack 漏洞成为了 side-channel attack 研究的早期里程碑。从 TENEX 的密码漏洞到现代的 Spectre/Meltdown 攻击，timing side channel 一直是计算机安全中最棘手的问题之一。TENEX 的教训提醒我们：系统的安全性是一个整体属性，任何层次的实现细节都可能成为攻击面。

从更广的视角看，TENEX 代表了一个重要的历史节点：虚拟内存从理论概念走向实用系统。Atlas 计算机（1962）首先提出了虚拟内存的概念，Multics 进行了更完整的实现，而 TENEX 则证明了虚拟内存可以在相对普通的硬件上（通过适度的硬件扩展）高效运行。这为后来虚拟内存成为所有通用操作系统的标准配置铺平了道路。
