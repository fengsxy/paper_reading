# A Fast File System for UNIX (FFS)

**McKusick, Joy, Leffler, Fabry, 1984**

---

## 1. 论文背景与动机

1984 年的这篇论文解决的是一个非常实际的问题：原始 UNIX 文件系统（通常称为 "old UNIX file system" 或 V7 FS）的性能已经糟糕到令人无法忍受的地步。

原始 UNIX 文件系统的设计非常简洁：磁盘被划分为一个 superblock、一个 inode 区域和一个数据区域。文件的数据块通过 inode 中的直接指针和间接指针来索引。这个设计在概念上很优雅，但在实际性能上却是灾难性的。

具体来说，原始 FS 存在以下严重问题：

- **块大小太小**：原始 FS 使用 512 字节的块大小（后来增加到 1024 字节）。这意味着读取一个大文件需要大量的磁盘 I/O 操作，每次只传输很少的数据，磁盘带宽利用率极低。实测表明，原始 FS 只能达到磁盘理论带宽的 2%–5%。

- **数据布局混乱**：随着文件系统的使用，文件的数据块会散布在整个磁盘上。更糟糕的是，inode 集中存放在磁盘的一端，而数据块分布在另一端，导致访问一个文件需要磁头在 inode 区和数据区之间来回寻道（seek），严重增加了访问延迟。

- **空闲块管理低效**：原始 FS 使用 free list 管理空闲块。随着时间推移，free list 变得随机化，新分配的块与文件的已有块之间没有空间局部性。

这些问题的根源在于：原始 UNIX 文件系统的设计完全没有考虑磁盘的物理特性。它把磁盘当作一个随机访问设备来使用，而实际上磁盘的性能高度依赖于数据的物理布局——顺序访问比随机访问快一到两个数量级。

## 2. 核心设计与关键创新

FFS（Berkeley Fast File System，也称为 BSD FFS 或 UFS）的核心思想是：文件系统的设计必须感知磁盘的物理结构，并据此优化数据布局。

### Cylinder Groups

FFS 将磁盘划分为多个 **cylinder group**。每个 cylinder group 包含若干相邻的柱面（cylinder），并且每个 group 都有自己的 superblock 副本、inode 表、数据块位图和数据块区域。

这个设计的关键洞察是：将相关的数据放在物理上相近的位置。具体的布局策略包括：

1. **文件的 inode 和数据块放在同一个 cylinder group 中**：这样访问一个文件时，读取 inode 和读取数据块之间的寻道距离很短。
2. **同一目录下的文件尽量放在同一个 cylinder group 中**：因为同一目录下的文件经常被一起访问（如 `ls -l`、编译一个项目等）。
3. **大文件的数据块分散到多个 cylinder group 中**：当一个文件增长到一定大小后，后续的数据块会被分配到其他 cylinder group。这看似违反了局部性原则，但目的是防止单个大文件占满一个 cylinder group，导致该 group 中的其他小文件无法获得局部性。

### 大块 + Fragment

FFS 将块大小从 512/1024 字节大幅增加到 4096 字节（甚至 8192 字节）。大块带来了显著的性能提升：每次磁盘 I/O 传输更多数据，减少了 I/O 次数，提高了带宽利用率。

但大块也带来了一个问题：小文件会浪费大量空间。如果一个文件只有 100 字节，却要占用一个 4096 字节的块，空间利用率不到 3%。为了解决这个问题，FFS 引入了 **fragment**（片段）机制：每个块可以被进一步划分为 2、4 或 8 个 fragment（通常为 512 字节）。文件的最后一个块可以只占用若干 fragment 而非整个块。这样既享受了大块的性能优势，又避免了小文件的空间浪费。

### Rotational Delay 优化

在 1984 年的磁盘技术下，磁盘的旋转延迟（rotational delay）是一个重要的性能因素。当磁头读完一个块后，磁盘继续旋转，如果下一个要读的块紧挨着当前块，磁头可能来不及处理就错过了，需要等待磁盘转一整圈。

FFS 通过感知磁盘的旋转速度和控制器的处理时间，在分配连续的逻辑块时，故意在物理上跳过若干扇区（rotationally optimal layout）。这样当磁头准备好读取下一个块时，该块恰好旋转到磁头下方。这个优化在当时的硬件条件下效果显著。

## 3. 重要的技术细节

### 位图 vs Free List

FFS 用位图（bitmap）替代了原始 FS 的 free list 来管理空闲块。位图的优势在于：可以快速找到物理上相邻的空闲块，从而实现上述的布局优化策略。Free list 则无法提供这种空间局部性信息。

### Superblock 冗余

每个 cylinder group 都保存一份 superblock 的副本，且这些副本在各 group 中的偏移量不同（避免它们都落在同一个盘面上）。这提供了对 superblock 损坏的容错能力——如果主 superblock 损坏，可以从任何一个 cylinder group 的副本中恢复。

### 长文件名和符号链接

FFS 还引入了一些与性能无关但对可用性很重要的改进：支持最长 255 字符的文件名（原始 FS 限制为 14 字符）、引入符号链接（symbolic link）、文件锁（advisory lock）等。这些功能虽然不是论文的核心贡献，但对 UNIX 的实际使用影响深远。

### 参数化磁盘特性

FFS 在文件系统创建时（mkfs）记录磁盘的物理参数：每磁道扇区数、旋转速度、磁头切换时间等。这些参数被用于计算最优的块布局。这种"感知硬件"的设计哲学是 FFS 性能提升的基础。

## 4. 优缺点分析

### 优点

1. **性能提升巨大**：FFS 将文件系统的吞吐量从磁盘带宽的 2%–5% 提升到 20%–40%，提升了近一个数量级。对于大文件的顺序读写，性能提升尤为显著。

2. **设计哲学正确**：FFS 确立了一个重要原则——文件系统必须感知底层存储设备的物理特性。这个原则影响了此后几十年的文件系统设计。

3. **空间效率与性能的平衡**：fragment 机制巧妙地解决了大块带来的空间浪费问题，在性能和空间利用率之间取得了良好的平衡。

4. **工程完整性**：FFS 不仅优化了性能，还引入了长文件名、符号链接等实用功能，是一个完整的工程成果。

### 缺点

1. **对磁盘参数的依赖**：FFS 的优化高度依赖于准确的磁盘物理参数。如果参数不准确（例如磁盘固件隐藏了真实的物理布局），优化效果会大打折扣。随着磁盘技术的发展（如 ZBR、NCQ 等），磁盘的物理特性变得越来越难以从外部准确获知。

2. **Rotational delay 优化的时效性**：随着磁盘控制器变得更智能（带有大容量缓存和命令队列），以及 SSD 的普及，rotational delay 优化变得不再必要。这部分设计已经过时。

3. **元数据更新的一致性**：FFS 没有提供崩溃一致性（crash consistency）的保证。系统崩溃后需要运行 fsck 扫描整个文件系统来修复不一致，这在大容量磁盘上可能需要很长时间。

4. **写性能仍有提升空间**：FFS 的写操作仍然涉及多次随机写（更新 inode、更新位图、写数据块等），对于写密集型工作负载，性能仍然不够理想。这正是后来 LFS 试图解决的问题。

## 5. 历史影响与后续发展

FFS 是文件系统发展史上最重要的里程碑之一。它确立的设计原则——感知存储设备物理特性、利用空间局部性优化布局——成为后续几乎所有文件系统设计的基础。

FFS 直接演化为 BSD 系统中的 UFS（Unix File System），并影响了 Linux 的 ext2/ext3/ext4 文件系统的设计。ext2 的 block group 概念直接来源于 FFS 的 cylinder group，只是去掉了对柱面物理结构的依赖（因为现代磁盘的 LBA 抽象使得柱面概念不再有意义）。

FFS 的 fragment 机制启发了后续文件系统中各种处理小文件的技术，如 ext4 的 inline data、ReiserFS 的 tail packing 等。

从更宏观的角度看，FFS 代表了系统软件设计中一个永恒的主题：抽象与性能之间的张力。操作系统提供抽象来简化编程，但高效的实现往往需要"穿透"抽象，感知底层硬件的特性。FFS 通过在文件系统层面感知磁盘的物理结构，在保持 UNIX 文件系统 API 不变的前提下，实现了数量级的性能提升。这种"在抽象层内部做硬件感知优化"的方法论，至今仍是系统设计的核心智慧。

对于操作系统课程的学生来说，FFS 是理解"为什么文件系统要这样设计"的最佳起点。它清晰地展示了从问题分析（原始 FS 为什么慢）到解决方案设计（cylinder group + 大块 + 布局优化）的完整思路，是系统研究方法论的经典范例。
