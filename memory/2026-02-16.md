## Latent Forcing 论文讨论 (深夜)

### 论文信息
- **标题:** Latent Forcing: Reordering the Diffusion Trajectory for Pixel-Space Image Generation
- **arXiv:** 2602.11401
- **作者:** Alan Baade, Eric Ryan Chan, Kyle Sargent, Changan Chen, Justin Johnson, Ehsan Adeli, Li Fei-Fei (Stanford)
- **会议:** ICML

### 核心思想
- 同时处理 latents 和 pixels，用不同的 noise schedule
- Latents 先 denoise（高层结构），pixels 后 denoise（低层细节）
- "Generation best starts with high-level structure before low-level detail"
- 这是图像生成论文，不是 LLM reasoning

### 与 dLLM 的类比
- Latents = 难 token（答案/关键词）— 先确定
- Pixels = 简单 token（CoT 细节）— 后填充
- 这和 Answer-Anchored CoT 思路一致

### DFlash + WeDLM 结合讨论

**Yu 的问题：** DFlash 能否和 WeDLM 结合，让 draft model 预测不同位置的信息？

**分析：**
- DFlash 原始：固定连续 block 位置
- WeDLM：解耦物理/逻辑位置，可预测任意位置
- 结合后：Draft model 可以选择 top-k confident 位置（不必连续）

**三个方案：**
1. **方案 A (分组验证):** 把选中位置按连续性分组，每组独立验证
2. **方案 B (dLLM-to-dLLM):** Target 也用 dLLM，不需要连续位置 — 最有意思
3. **方案 C (选连续区间):** 只选最长的连续高 confidence 区间

**方案 B 的优势：**
- 传统 spec decoding: AR draft → AR verify（必须连续）
- dLLM-to-dLLM: dLLM draft → dLLM verify（任意位置，并行验证）

**挑战：**
1. 大 dLLM 目前不存在（大模型都是 AR）
2. dLLM 验证和 AR 验证的分布一致性？
3. 工程复杂度

**更实际的方向：方案 C**
- 保持 DFlash 的 AR target
- 用 WeDLM 风格的 draft 选择 "最容易被接受的连续区间"

### 论文与 dLLM 研究的关联

**最直接相关：**
1. **Wright-Fisher** → dLLM 理论基础，selection coefficient 可能解释 optimal ordering
2. **IEM** → Token difficulty metric，可用于 difficulty-based ordering
3. **Hot Mess** → Incoherence 分析，optimal ordering 目标 = minimize variance

**间接相关：**
4. **Parallel Token Gen** → 竞争方法，flow 的 Jacobian 分析 token 依赖
5. **Drifting Models** → One-step 思想
6. **Diffusion Compression** → 压缩视角，"容易压缩" = "先生成"

### 综合启发：Optimal Ordering 理论框架

1. **定义 Token Difficulty** (IEM): $D_i = \mathbb{E}[\text{denoising error at position } i]$
2. **定义 Optimal Ordering** (Hot Mess): $\text{order}^* = \arg\min_{\text{order}} \text{Variance}[\text{output}]$
3. **理论工具** (Wright-Fisher): Selection coefficient ↔ Token difficulty

### 关键发现

**Self-Rewarding SMC:**
- 用 trajectory-level confidence 作为 importance weight
- 并行 particles 可以转化为质量提升
- 这是 dLLM 相对于 AR 的独特优势

**SOAR:**
- 低 confidence 时搜索（避免过早 commit）
- 高 confidence 时加速（并行解码）
- 自适应策略可以同时提升质量和速度

**RDD:**
- 检测 stagnation（reverse process 不再进展）
- 回退 + confidence-guided re-masking
- Training-free 的错误恢复机制

**XDLM:**
- 用 stationary noise kernel 统一 MDLM 和 UDLM
- MDLM 擅长理解，UDLM 擅长生成
- 混合可以取长补短
