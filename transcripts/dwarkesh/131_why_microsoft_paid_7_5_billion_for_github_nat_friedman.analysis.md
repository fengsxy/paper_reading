# Analysis: Why Microsoft paid $7.5 billion for GitHub

## 0. 3-5 句摘要

Nat Friedman 讲述了他如何在加入微软第一周就向 Satya 提议收购 GitHub，以及这笔 $7.5B 收购背后的战略逻辑。核心论点是：软件采购决策权正在从 IT 部门转移到开发者手中，而微软作为一家"IT 公司"正在失去整整一代对微软没有亲和力的新开发者——GitHub 是接触这些开发者的最大入口。Satya 在 6-7 分钟内回复了 Nat 的备忘录，说"this is very good thinking"。

## 1. 反共识/非显然观点

- **"微软的第一个产品是编程语言，但它变成了 IT 公司"** [01:41]：Nat 指出了微软身份的根本矛盾——它诞生于开发者文化，但在 Windows/Office 时代变成了面向 IT 采购的公司。收购 GitHub 是"回归创始基因"。

- **"仅仅做到'competent'就够了"** [02:05]：Nat 的论点不是"我们要把 GitHub 做得更好"，而是"如果我们仅仅做到不搞砸，就能赢得整代开发者的好感"。这是一个极其务实的收购逻辑。

- **"Google 可能在'sniffing around'是 GitHub 团队制造的"** [01:04]：Nat 怀疑 Google 对 GitHub 的兴趣可能是 GitHub 团队为了推动收购而制造的竞争压力——但他认为这是一个好的催化剂。

## 2. 可学习的点（可迁移的方法论）

- **"第一周就提大想法"的策略** [00:41]：Nat 在加入微软第一周就向 CEO 提议 $7.5B 收购。这种"新人不受组织惯性约束"的窗口期是提出大胆想法的最佳时机。

- **"开发者 → 采购决策"的权力转移** [01:27]：识别"谁在做购买决策"的转移是任何 B2B 战略的核心。Nat 看到了从 IT 到开发者的转移，这个洞察价值 $7.5B。

## 3. 提问技巧（采访方法）

- **让嘉宾讲"origin story"**：Dwarkesh 让 Nat 从头讲起——从 Xamarin 被收购到第一周见 Satya——这种叙事结构自然地揭示了决策过程和人物关系。

## 4. 可进一步验证/挖坑

- **GitHub 收购的 ROI**：$7.5B 收购后，GitHub 的收入增长了多少？Copilot 的收入是否已经超过了收购价？这可能是科技史上 ROI 最高的收购之一。
