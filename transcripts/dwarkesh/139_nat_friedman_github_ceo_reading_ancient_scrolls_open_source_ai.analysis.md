# Analysis: Nat Friedman (Github CEO) — Reading ancient scrolls, open source, & AI

## 一句话

一个连续创业者如何用「世界并不高效」的信念，把古卷解读、GitHub 收购、Copilot 产品化这些看似不相关的事串成同一套行动哲学——找到没人做的高杠杆事情，用热情驱动自己冲进去，然后靠执拗把它做完。

## 关键洞察

- **[00:26] 世界并不高效，别假设有人在做。** Nat 反复强调他不再有「如果这是好主意，别人早就在做了」的本能反应。这个认知转变是他所有行动的底层操作系统——从 Vesuvius Challenge 到收购 GitHub，都源于此。他还用对冲基金的例子佐证：顶级基金的 30 天前策略如果公开，利润会下降 80%；10 年的 look-back window 才能让影响变小。世界的低效程度远超我们的默认估计。

- **[08:11] 用 prize/competition 模式加速科研突破。** Vesuvius Challenge 的核心逻辑是：关键技术组件已经被 Dr. Brent Seales 团队验证（CT 扫描 + CNN 识别墨迹），但搜索空间太大，单一团队探索太慢。开放竞赛让大量聪明人同时尝试不同路径，「many eyes make it shallow」。这是一种用金钱换时间、用并行换串行的策略。

- **[43:28] GitHub 收购后第一天的「ship one thing」策略。** Nat 上任 CEO 第一天就打开社区反馈列表，要求团队当天修复一个问题并发布。连续 100 天每天如此。这不仅赢得了开发者信任，更重要的是建立了三个反馈循环：用户满意的多巴胺循环、团队 shipping 的动力循环、CEO 快速学习组织能力的认知循环。

- **[50:28] Copilot 的产品形态是试错出来的，不是设计出来的。** 最初原型是 Q&A chatbot（不够可靠），然后是大块代码合成（体验不好），再到多选项函数体生成（认知负担太重），最终收敛到「根据 AST 位置自动决定补全粒度 + 灰色内联文本」的形态。关键洞察：AI 产品的 demo 总是很惊艳，但从 demo 到好产品之间有巨大的鸿沟，需要反复迭代 UI 和交互细节。

- **[1:19:16] 应该鼓励有优秀判断力的人 micromanage。** 文化上对 micromanagement 的禁忌导致真正有好判断力的人被迫放弃自己的判断，结果是团队产出趋向平庸的共识。Nat 更偏好高方差结果——要么因为优秀个体的 vision 而卓越，要么彻底失败然后快速重来，而不是永远输出平庸的中间态。

## Takeaway

- **找到你的「Vesuvius Challenge」：** 当你对某件事持续感到兴奋，而且发现「居然没人在做」，不要用「世界是高效的」来说服自己放弃。低激活能量 + 持续热情 + 执拗不放弃，这个组合本身就是一种稀缺的竞争优势。

- **AI 产品的正确迭代路径：** 不要从「技术能做什么」出发设计产品，而是从「用户在什么场景下愿意接受 AI 的不完美」出发。Copilot 成功的关键不是模型能力，而是找到了「自动补全」这个用户对错误容忍度最高的交互形态——错了就忽略，对了就 Tab 接受，认知成本极低。

## 延伸

- **Vesuvius Challenge / scrollprize.org** — Nat Friedman 和 Daniel Gross 发起的古卷解读竞赛，后来在 2023 年底真的成功读出了文字
- **Dr. Brent Seales** — University of Kentucky 教授，virtual unwrapping 技术的先驱，用 CT 扫描 + 机器学习非破坏性读取古卷
- **The Innovator's Dilemma (Clayton Christensen)** — Nat 认为这本书改变了大公司的行为模式，让它们学会了避免被颠覆
- **Nadia Asparouhova (Nadia Eghbal)** — 《Working in Public》作者，研究开源软件维护者的社区负担问题
- **Herculaneum Papyri** — 公元 79 年维苏威火山掩埋的古代图书馆，可能包含古代文学、哲学、甚至早期基督教相关文本
- **Igor Babushkin** — 曾在 DeepMind 和 OpenAI 训练 SOTA 模型，后加入 Twitter/X，是 AI 人才流动和秘密扩散的典型案例
