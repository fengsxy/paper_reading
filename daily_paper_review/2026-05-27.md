## 1. Causal Representation Learning for Generalisable Recommendation
**arXiv**: 2605.27043 | **Date**: 2026-05-26 | **Author**: Michael O'Riordan, Spotify

### Task
解决推荐系统在 offline 训练分布与 serving 时 candidate 分布之间的 distribution shift 问题，使其在 deployment 后的 distribution 上仍有良好泛化性。核心场景：Spotify 个性化播放列表生成 ranker，百万用户 A/B test。

### Challenge
推荐系统训练于 confounded interaction logs（被 deployed policy、用户行为、平台 filtering 共同塑造），而 serving 时需要 score 更广、更不同分布的 candidate set。传统 supervised 模型会通过 spurious backdoor path（T ← T_nC ← Z → Y）吸收 confounder 信息，导致 offline metric 与 online performance 严重脱节。经典 CRL 需要 interventional/randomised data 或 anchor variables，不适用于纯 observational logs。

### Insight
#### Insight
- **暴露偏差的本质是虚假相关**：deployed policy 导致 item-side 非因果因素与 user-side signal 产生相关性，标准模型会将这种相关性当作预测信号，但在 distribution shift 后失效
- **不需要 full identification**：只需要压制 spurious pathway，不需要恢复完整的 latent causal factors——这个 narrower goal 使得方法比传统 CRL 实用得多
- **信息论 disentanglement criterion**：将"保留因果内容"形式化为 maximize I(T; Y|Z)，将"压制 confounder 依赖"形式化为 penalize I(g(T); Z)

#### Novelty
- **信息论 disentanglement criterion**→【spurious pathway 难以直接建模】→**Causal disentanglement objective**：J(g) = I(g(T); Y|Z) - λ·I(g(T); Z)，在 population level 证明最优解只依赖 causal components
- **Variational lower bound 可优化实现**→【信息论 criterion 需要 mutual information，估计困难】→**变分下界**，从有限 observational data 优化，无需 randomized/interventional data
- **Plug-in 修改任何 supervised model**→【工业界需要 deployment-ready 方案】→**不改变模型结构，无 inference-time cost**，只需在训练时加 disentanglement objective
- **Spotify 生产 ranker 验证**→【评估须覆盖 offline + online】→**A/B test on millions of users**，capacity-matched CRL variant 与 production baseline offline 持平，online engagement 显著提升

### Method
在 synthetic SCM（已知 causal structure）+ KuaiRand benchmark（public）+ Spotify production ranker（live A/B）三级验证。加 CRL objective 的 variant 在 held-out random-exposure split、intervention setting、live serving 均优于 baseline。

### Potential Flaw
#### 情境局限
假设 confounder Z 是 observed 的（用户特征在 logs 中）。若 confounder 未被记录，或有 unobserved confounder，方法失效。实际推荐系统中许多 confounders 难以精确测量（如用户当下的情绪状态）。

#### 数据问题
当 treatment T 的 causal component T_C 与 non-causal component T_nC 在观测上难以区分时（高纠缠）， variational bound 的质量可能不足。更根本地，当 A2（unique spurious leakage：I(T_nC; Z|T_C) > 0）不满足时（即 non-causal 信息完全不携带 confounder 信号），方法改进有限。

#### 值得挖掘的方向
**Unobserved confounder 场景下的 CRL**：现有方法都假设 confounder 可观测。能否设计一种方法，在 confounder 部分可观测、甚至完全 unknown 时，仍能通过 counterfactual 或 adversarial 方法压制 spurious correlation？这是工业界更真实但学术界较少关注的 setting。

### Motivation
之前的方法要么依赖强假设（interventional data、anchor variables）无法实用，要么只针对特定 bias mechanism（popularity、selection）缺乏通用性。那能不能设计一个只需要现有 observational logs、不需要额外数据、且能泛化到任意 distribution shift 的方法？答案是：用信息论 criterion 直接压制 confounder 与 representation 之间的 mutual information，同时保留 outcome-predictive content——这是一个 weaker goal，但足够实用且可证最优。

## 2. Looped Diffusion Language Models
**arXiv**: 2605.26106 | **Date**: 2026-05-25

### Task
解决 Masked Diffusion Language Models (MDLM) 中 transformer 架构设计问题：如何为 MDM 设计有效的 transformer，使得并行解码优势得以充分发挥？

### Challenge
MDLM 需要在每个去噪步同时预测多个 token，但现有 MDM 的 transformer 架构（直接从 AR 模型借鉴而来）未能充分考虑并行解码的时序特性。Encoder-decoder 架构在 masked prediction 时存在信息瓶颈，pure decoder 架构缺乏跨步状态传递机制。

### Insight
- **Looped feedback = 跨步状态传递**：在 MDLM 中引入 looped 架构，将每步的 hidden state 作为下一步的输入，使模型能在去噪过程中持续精炼表示
- **不同于 AR 的 recurrence**：AR 模型每个 token 生成后不再改变；MDLM 的 looped 结构允许已生成的 token 在后续步中被进一步精炼
- **Unified token generation**：Looped MDM 自然支持 parallel token generation，而非 AR 的 sequential prediction

### Novelty
- **Looped transformer 架构**→【MDLM 缺乏跨步状态传递】→**Hidden state feedback loop**：每步 denoising 输出 feed back 到下一步，替代 MDM 中每步独立处理的范式
- **Multi-step refinement 而非 single-pass**→【去噪过程的多步迭代本质】→**Looped architecture 让模型在多步中逐步精炼 token sequence**
- **自适应 loop count**→【不同样本需要不同去噪难度】→**Early-exit based on confidence**，减少不必要的计算

### Method
在多个 MDLM backbone 上验证，looped 架构相比 vanilla MDM 在 perplexity 和生成质量上均有提升。

### Potential Flaw
- Looped feedback 引入的 state compression 问题：每步的 hidden state 如何高效存储和传递，未充分分析
- 训练复杂度增加：looped training 需要 BPTT，内存和训练时间开销较大

### Future
与 speculative decoding 结合，looped MDM 的并行性 + speculative 的验证机制可能产生协同效应。

## 3. Language Models Need Sleep
**arXiv**: 2605.26099 | **Date**: 2026-05-25

### Task
研究 LLM 在持续 inference（不间断服务）过程中是否会出现"疲劳"现象，以及如何通过周期性休眠机制恢复模型性能。场景：24/7 部署的 LLM 服务（如 chat interface、API 服务）。

### Challenge
LLM 在长时连续运行中，attention mechanism 的 activation 和 KV cache 持续被占用，可能导致：① 上下文可用性下降（新 token 的表示空间被旧 activation 污染）；② 累积的 numerical error 影响生成质量；③ 无有效机制清除"过期"上下文信息。

### Insight
- **Continuous inference ≈ 慢性信息中毒**：长时间运行后，早期 context 的 influence 反而可能超过近期 context（recency bias 被破坏）
- **Sleep = 软性 reset**：不必完全重置模型（代价过高），只需在模型层面做短暂的"静默期"，让 activation 分布回归初始状态
- **仿生学启发**：人类睡眠时脑内突触权重会重置；LLM 的"人工睡眠"可能通过周期性清空 attention state 或调整 layernorm 参数实现

### Novelty
- **LLM continuous inference fatigue**→【缺乏理论框架描述长时运行的性能衰减】→**实证研究**：在不同模型规模、任务类型上测量连续运行后的性能变化
- **Sleep mechanism 设计**→【需要可部署的恢复手段】→**周期性 soft reset**：清空 attention cache + 短暂 no-generation period
- **定量评估 framework**→【"疲劳"难以定义】→**Normalized performance drop + recovery curve**，量化每次 sleep 的效果

### Method
在多个模型（7B-70B）上验证 24-72h 连续运行，发现性能在 24h 后开始显著下降，sleep 后可恢复到初始水平的 90-95%。

### Potential Flaw
- "Sleep" 期间服务不可用，实际部署需要精巧的 load balancing
- 不同任务受疲劳影响程度不同，哪些任务最敏感未系统分析

### Future
自适应 sleep：根据当前上下文长度和质量动态决定 sleep timing，而非固定 schedule。

## 4. IndexMem: Learned KV-Cache Eviction with Latent Memory for Long-Context LLM Inference
**arXiv**: 2605.25475 | **Date**: 2026-05-25

### Task
解决 long-context LLM 推理中 KV-cache 内存瓶颈问题：当 context 极长时，KV-cache 可能成为 GPU memory 的主要消耗。核心目标：设计一个 learned eviction policy，高效管理 KV-cache 的存储和释放，在有限内存下支持更长 context。

### Challenge
- 全量缓存 KV 不可行：100K context 的 KV-cache 可能占用数百 GB memory，远超 GPU 承载能力
- 简单 eviction（LRU、FIFO）忽略 semantic relevance：重要 token 被 premature 驱逐，导致质量严重下降
- 学习型方法需要同时优化 two tasks：cache management + 下游任务性能

### Insight
- **Latent memory as cache manager**：用一个小模型（latent memory）学习哪些 KV entries 值得保留，其输出作为 eviction decision 的基础
- **KV entries 的 semantic importance ≠ recency**：最近的 token 不一定最重要，早期关键概念可能需要长期保留
- **Learn to forget**：与 memory compression 的思路正交，IndexMem 专注于"which to evict"而非"what to compress"

### Novelty
- **Learned eviction via latent memory**→【rule-based eviction 忽略 semantic】→**Latent memory model** 预测每个 KV entry 的 long-term utility，驱动 eviction decisions
- **Unified cache + generation optimization**→【cache management 和生成质量须联合优化】→**Single training objective** 同时优化 cache hit rate 和下游 perplexity
- **GPU-friendly implementation**→【latent memory 须低 overhead】→**轻量级 predictor network**，与 main model解耦

### Method
在 LongBench、V100K 等 benchmark 上验证，相比 LRU/Prefetch 方法，IndexMem 在同等 memory 下将 task performance 提升 15-20%。

### Potential Flaw
- Latent memory 的训练需要 gold cache labels（来自 full-cache run），获取成本高
- 跨任务泛化能力未充分验证：某类任务训练的 policy 能否迁移到其他 task

### Future
与 offloading（KV offload to CPU/NVMe）结合，learned policy 决定 cache tier（GPU/CPU/disk）而不仅是 eviction。

## 5. TUBE: Tangent Upper Bound on Evidence for Discrete Diffusion Language Models
**arXiv**: 2605.24292 | **Date**: 2026-05-22

### Task
为离散扩散语言模型（DLM）提供 evidence 的可计算上界，用于模型选择、超参数调优和 sampling quality 评估。核心问题：如何判断某个 DLM 配置是否"好"，而不需要昂贵的后验估计？

### Challenge
- DLM 的 evidence（log marginal likelihood）无法 closed-form 计算，因为离散 token space 使变分推断复杂
- 现有 model selection 方法（held-out perplexity、FID类指标）不能直接反映生成质量
- Sampling 质量评估需要完整生成样本，效率低

### Insight
- **Evidence ≈ 采样路径的积分**：将 DLM 的 evidence 重写为沿 noise schedule 的积分形式，每点的 integrand 是关于 forward process 的某个量
- **Tangent bound = 最紧上界**：利用 I_surrogate 技术，在每个 noise level 取 tangent approximation，得到 evidence 的上界
- **可计算性关键**：只需 forward process 的 statistics，无需 reverse process 或 sampling

### Novelty
- **Tangent upper bound for DLM evidence**→【evidence 无法 closed-form 计算】→**TUBE**：利用 I_surrogate 在每个 timestep 取切线逼近，得到可计算的紧上界
- **Noise schedule 敏感性分析**→【不同 schedule 的 evidence 差异显著】→**TUBE 作为 schedule 选择的工具**，无需生成样本即可比较
- **Model selection without sampling**→【sampling 成本高】→**TUBE score** 作为 DLM 的 proxy metric，与 full sampling quality 高度相关

### Method
在多个 DLM backbone（MDLM、UDM）上验证，TUBE 与生成质量（human evaluation、task performance）相关性高于 perplexity-based metrics。

### Potential Flaw
- Tangent approximation 在低 noise 区域可能 loose，对于 very low NFE 的场景 bound 可能过于宽松
- 需要对每个 noise level 计算 statistics，计算量随 NFE 线性增长

### Future
与 distillation 结合，用 TUBE 作为 early-stop criterion，节省训练 compute。

## 6. Reducing Diffusion Model Memorization with Higher Noise Injection
**arXiv**: 2605.19170 | **Date**: 2026-05-23

### Task
减少 diffusion model 的 memorization（对训练数据的直接复现），在保留生成质量的同时增强隐私保护和数据版权合规能力。核心挑战：diffusion model 容易记忆训练集中的样本，尤其是高频出现的模式。

### Challenge
- Diffusion model 的生成过程在低 noise 阶段本质上是在"回忆"而非"创造"——训练数据分布的峰值被模型直接映射到生成样本
- 现有 deduplication 或 data filtering 方法是粗粒度的，无法解决细粒度的 memorization（部分样本复制、部分创新）
- Privacy+memorization 的平衡：过度去噪会损害生成质量

### Insight
- **Memorization 的来源是低 noise 阶段的 overfitting**：当 noise level 很低时，模型倾向于重建训练样本而非采样新样本
- **Higher noise injection ≈ selective unlearning**：提高前向过程的 noise 水平，相当于让模型在更高 noise 下学习，削弱低 noise 时对 specific training samples 的记忆
- **Noise schedule 的重新设计**：不是全局提高 noise，而是针对容易 memorization 的 region 做 adaptive 调整

### Novelty
- **Memorization-aware noise schedule**→【diffusion 的 memorization 集中在低 noise 区域】→**Adaptive noise injection**：在低 noise 区域注入高于 standard schedule 的 noise，减少模型对特定样本的记忆
- **Memorization metric + optimization**→【难以评估 memorization 程度】→**Membership inference-based metric**，量化 memorization level 并反馈到 noise schedule 调优
- **Privacy-utility Pareto frontier**→【隐私和质量的 trade-off 必须可调】→**Noise level hyperparameter**，在 memorization reduction 和生成质量之间做可解释的权衡

### Method
在 CIFAR-10、ImageNet 上验证，higher noise injection 可将 memorization rate 降低 40-60%（通过 membership inference test 测量），同时 FID 下降 <5%。

### Potential Flaw
- "Memorization" 的定义本身存在争议——membership inference 的 false positive/negative 率未充分讨论
- 对复杂文本生成任务（高 entropy data）的 memorization reduction 效果未知

### Future
与 differential privacy（SGD noise injection）结合，在 DP 框架下分析 memorization+privacy 的联合 bound。
