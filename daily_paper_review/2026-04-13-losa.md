# Daily Paper Review — 2026-04-13

**Paper**: LoSA: Locality Aware Sparse Attention for Block-Wise Diffusion Language Models
**arXiv ID**: 2604.12056v1
**Date**: 2026-04-13
**Tag**: dLLM / Efficiency / Sparse Attention / KV Cache

---

## 1. Task

**问题形式化**：

Block-wise dLLM 在长上下文场景下受制于 **memory-bound attention**。虽然 block 生成多个 token，但 attention 仍是 O(N^2) 密集计算。

Naive sparse attention 在 dLLM 上失效——原因是 **KV Inflation 问题**：

> 在 AR 模型中，每个 query 只attend 前面的 token，KV cache 是单调增长的。
> 在 dLLM 中，不同 query 在不同 step 会attend 不同的 prefix 位置，因为去噪顺序是动态的。
> 因此，naive sparse 下不同 query 选中的 KV 位置集合差异很大，union 后的 KV 页面数量几乎等于 full attention。

**目标**：识别 dLLM 的 token 稳定性（stable vs active），只对 active tokens 做 sparse attention，复用 stable tokens 的 cached attention 结果。

---

## 2. Challenge

| 方法 | 困境 |
|------|------|
| Naive sparse attention | KV Inflation——不同 query 的稀疏位置不同，union 仍很大 |
| Full attention | O(N^2) 内存，long context 无法承受 |
| Static sparsity pattern | dLLM 的去噪顺序动态变化，静态模式不适用 |

**根本问题**：dLLM 的去噪顺序是动态的，无法用 AR 的静态 causal mask 预先计算稀疏模式。

---

## 3. Insight & Novelty

### 3.1 Insight

**核心发现（关键观察）**：

> 在连续去噪 step 之间，只有少数 active tokens 的 hidden state 发生显著变化，绝大多数 stable tokens 几乎不变。

这意味着：**连续 step 间的 attention 结果大量是可复用的**。

**关键推理**：KV Inflation 的根源不是"需要 attention 的 token 多"，而是"不同 query 在不同 step 需要的 KV 位置不一致"。但如果我们能识别 stable tokens（hidden state 不变的 token），这些 token 的 KV 在连续 step 间几乎相同，可以直接复用上一步的 attention 结果。

### 3.2 Novelty

**创新点 1**：识别 dLLM 中 stable vs active token 的标准
- **解决的问题**：如何在每个 step 判断哪些 token 是 stable 的
- **受启发于**：连续 step 间 hidden state 变化的观察
- **具体设计**：计算每个 token 在连续 step 间 hidden state 的 L2 范数变化，超过阈值为 active，否则为 stable

**创新点 2**：Stable token 的 cached attention reuse
- **解决的问题**：如何避免 KV Inflation
- **受启发于**：stable token 的 KV 在连续 step 间几乎不变
- **具体设计**：对 stable token，直接复用上一步的 attention 输出；对 active token，只对当前 query 相关的局部窗口做稀疏计算

**创新点 3**：Active token 的局部稀疏 attention
- **解决的问题**：如何高效处理 active token
- **受启发于**：dLLM 的局部性——active token 的 most relevant context 通常在局部
- **具体设计**：只对 active token 相关的局部窗口做 attention，而非 full prefix

---

## 4. Potential Flaw

### 4.1 情境局限

- **长上下文专项优化**：对短文本任务（≤ 512 tokens）收益有限，因为 stable/active 的区分收益在长序列才明显
- **不同 dLLM 架构效果可能不同**：只在特定 block-wise dLLM 上验证，masked dLLM 的效果未知
- **阈值敏感性**：stable/active 的 L2 threshold 需要调优，不同模型最优阈值可能不同

### 4.2 数据问题

- **密集 attention 数据**（如 code、表格）：active token 比例可能系统性偏高，sparse 收益降低
- **稀疏 attention 数据**（如新闻、narrative text）：收益更高

### 4.3 值得挖掘的方向

**最值得做的**：LoSA + KV cache 统一设计。

> LoSA 解决的是"哪些 token 的 KV 可以复用"，但没有解决"如何与 block-wise decoding 配合"——每个 block 的 boundary 可能是跨 stable/active boundary 的。
>
> 如果结合 LoSA 和 VSB：VSB 决定 block boundary，LoSA 负责每个 block 内 stable tokens 的 KV reuse。这是一个系统级的 dLLM efficiency 优化。

**另一方向**：将 LoSA 的 hidden state change 判别标准与 **temporal stability**（SWD 中的 KL divergence）结合——L2 norm change 和 KL divergence 都是衡量 token "稳定性"的指标，哪个更准？

---

## 5. Motivation

**General idea 推导路径**（第一性原理）：

> AR 模型：每个 token 生成后永久进入 KV cache，cache 是单调增长的——所以 AR 的 KV cache 问题有成熟解决方案。
>
> dLLM 不同：block 内所有 token 同时生成，但 attention 的 query 是每个位置的当前 hidden state。这个 hidden state 在连续 step 间变化。
>
> **那问题来了：hidden state 在连续 step 间变化的速度是一样的吗？**
>
> 不是。有些 token 很快收敛，它们的 hidden state 在第一个 step 后就几乎不变了；有些 token 需要很多 step 才能收敛。
>
> **这意味着：早期 step 的 attention 结果，对已收敛 token 来说是可以复用的。**
>
> 但 naive sparse attention 不知道这一点——它对所有 token 一视同仁，所以不同 query 选出的稀疏位置不同，KV union 仍然很大。
>
> 所以解决方案是：**识别哪些 token 已经收敛，对已收敛 token 复用缓存结果，对未收敛 token 做稀疏计算。**
>
> 这不是工程优化，这是利用 dLLM 内在的时间结构。
