# Towards an Information-Theoretic Framework for Optimal Token Ordering in Discrete Diffusion Language Models

**Draft Date:** 2026-02-16  
**Author:** Longxuan Yu  
**Status:** Working Draft

## Abstract

Discrete diffusion language models (dLLMs) generate tokens in a non-autoregressive manner, where the order of token generation is a critical design choice. Empirical work (McDiffuSE, DAWN) demonstrates that ordering significantly impacts generation quality, yet no theoretical framework explains *why* certain orderings outperform others or *how* to learn optimal orderings. This draft proposes an information-theoretic framework that formalizes the ordering problem through the lens of mutual information maximization and conditional entropy reduction.

---

## 1. The Ordering Gap: What We Know and Don't Know

### 1.1 Empirical Evidence

**McDiffuSE (2024):** Demonstrated that for speech enhancement, ordering tokens by confidence (high-to-low) significantly outperforms random ordering. Key finding: *ordering matters*, but no theoretical justification provided.

**DAWN (2024):** Introduced dependency graphs to model inter-token relationships, using graph-based scheduling for generation order. Limitation: dependency structure is heuristic, not learned.

**MDLM, SEDD, etc.:** Most dLLM work uses uniform random masking/unmasking, implicitly assuming ordering doesn't matter—contradicted by McDiffuSE/DAWN results.

### 1.2 The Theoretical Void

Current state:
- ✅ Ordering affects quality (empirically proven)
- ❌ No theory explaining *why*
- ❌ No principled method to *learn* optimal ordering
- ❌ No understanding of task-dependent ordering

**Core Question:** What makes one ordering better than another, and can we derive optimal orderings from first principles?

## 2. Information-Theoretic Formulation

### 2.1 Setup and Notation

Let $\mathbf{x} = (x_1, x_2, \ldots, x_n)$ be a sequence of $n$ tokens.

Let $\pi: \{1, \ldots, n\} \to \{1, \ldots, n\}$ be a permutation defining the generation order.

At step $t$, we have:
- $\mathbf{x}_{\pi_{<t}}$: tokens already generated (positions $\pi(1), \ldots, \pi(t-1)$)
- $\mathbf{x}_{\pi_{\geq t}}$: tokens yet to be generated

### 2.2 The Ordering Objective

**Hypothesis:** The optimal ordering $\pi^*$ minimizes the total conditional entropy across the generation process:

$$\pi^* = \arg\min_\pi \sum_{t=1}^{n} H(x_{\pi(t)} | \mathbf{x}_{\pi_{<t}})$$

**Intuition:** Generate tokens in an order where each subsequent token is maximally predictable given previously generated tokens.

### 2.3 Connection to Mutual Information

Equivalently, we can frame this as maximizing the mutual information gained at each step:

$$\pi^* = \arg\max_\pi \sum_{t=1}^{n} I(x_{\pi(t)}; \mathbf{x}_{\pi_{>t}} | \mathbf{x}_{\pi_{<t}})$$

**Interpretation:** At each step, generate the token that provides the most information about the remaining tokens.

## 3. Theoretical Analysis

### 3.1 Why Left-to-Right Works for Language

For natural language, left-to-right ordering is often near-optimal because:

1. **Syntactic Dependencies:** Subject typically precedes verb, which precedes object
2. **Discourse Structure:** Topic introduction precedes elaboration
3. **Information Flow:** Given information precedes new information (information structure)

**Proposition 1:** For sequences generated by a left-to-right process (e.g., human writing), the left-to-right ordering achieves:

$$H(x_t | x_{<t}) \leq H(x_t | x_S) \quad \forall S \subset \{1, \ldots, t-1\}$$

This explains why AR models are strong baselines—they match the data generation process.

### 3.2 When Non-L2R Orderings Win

Non-left-to-right orderings can outperform when:

1. **Structural Constraints:** Code with matching brackets, structured data
2. **Global Dependencies:** Poetry with rhyme schemes, music with harmonic structure
3. **Bidirectional Context:** Fill-in-the-middle tasks, editing

**Proposition 2:** For sequences with long-range bidirectional dependencies, there exists an ordering $\pi$ such that:

$$\sum_{t=1}^{n} H(x_{\pi(t)} | \mathbf{x}_{\pi_{<t}}) < \sum_{t=1}^{n} H(x_t | x_{<t})$$

**Example:** For a rhyming couplet "The cat sat on the mat", generating "cat" and "mat" early (due to rhyme constraint) reduces uncertainty for intermediate tokens.

### 3.3 The Greedy Approximation

Computing $\pi^*$ exactly is intractable (requires evaluating $n!$ orderings). 

**Greedy Algorithm:**
```
At each step t:
  π(t) = argmin_{i ∈ remaining} H(x_i | x_{π_{<t}})
```

**Theorem (Informal):** Under submodularity assumptions on the entropy function, the greedy algorithm achieves a $(1 - 1/e)$ approximation to the optimal ordering.

## 4. Learning the Ordering

### 4.1 The Learning Problem

Instead of computing orderings at inference time, we want to *learn* an ordering policy:

$$\pi_\theta: \mathbf{x}_{\text{partial}} \to \text{next position to generate}$$

### 4.2 Proposed Approaches

#### Approach A: Confidence-Based Ordering (McDiffuSE style)

Use model confidence as a proxy for conditional entropy:

$$\pi(t) = \arg\max_{i \in \text{remaining}} \max_v p_\theta(x_i = v | \mathbf{x}_{\pi_{<t}})$$

**Limitation:** Confidence ≠ information gain; high confidence on an isolated token may not help predict others.

#### Approach B: Learned Ordering Network

Train a separate network $\phi$ to predict optimal orderings:

$$\mathcal{L}_\phi = \mathbb{E}_{\mathbf{x} \sim p_{\text{data}}} \left[ \sum_t H(x_{\pi_\phi(t)} | \mathbf{x}_{\pi_\phi(<t)}) \right]$$

**Challenge:** Requires differentiable ordering (e.g., Gumbel-Sinkhorn).

#### Approach C: Reinforcement Learning

Treat ordering as a sequential decision problem:
- State: partially generated sequence
- Action: which position to generate next
- Reward: negative conditional entropy (or downstream task metric)

**Advantage:** Can optimize for task-specific objectives beyond entropy.

### 4.3 Dependency Graph Learning (Extending DAWN)

DAWN uses heuristic dependency graphs. We propose *learning* the graph:

$$G_\theta(\mathbf{x}) = \text{adjacency matrix of token dependencies}$$

**Training Objective:**

$$\mathcal{L}_G = \mathbb{E}_{\mathbf{x}} \left[ \sum_{i,j} G_{ij} \cdot I(x_i; x_j | \mathbf{x}_{\setminus\{i,j\}}) \right]$$

**Topological Sort:** Generate tokens in topological order of the learned graph.

## 5. Connections to Existing Theory

### 5.1 Optimal Coding and Huffman Trees

The ordering problem is analogous to optimal prefix coding:
- Huffman coding: assign shorter codes to more probable symbols
- Optimal ordering: generate more predictable tokens first

**Insight:** Just as Huffman coding minimizes expected code length, optimal ordering minimizes expected generation difficulty.

### 5.2 Information Bottleneck

The ordering problem can be viewed through the Information Bottleneck lens:

$$\min_\pi I(\mathbf{x}_{\pi_{<t}}; \mathbf{x}) - \beta I(\mathbf{x}_{\pi_{<t}}; x_{\pi(t)})$$

**Interpretation:** Balance between compressing the context and preserving predictive power.

### 5.3 Causal Discovery

Learning token dependencies is related to causal structure learning:
- Tokens with causal relationships should be generated in causal order
- PC algorithm, GES, etc. could inform dependency graph learning

## 6. Experimental Predictions

### 6.1 Testable Hypotheses

**H1:** Entropy-minimizing orderings outperform random orderings across tasks.

**H2:** Task-specific optimal orderings differ (code vs. prose vs. dialogue).

**H3:** Learned orderings outperform heuristic orderings (confidence, dependency graphs).

**H4:** The gap between optimal and L2R ordering is larger for structured outputs.

### 6.2 Proposed Experiments

1. **Oracle Experiment:** Compute entropy-optimal ordering via exhaustive search on short sequences; compare to heuristics.

2. **Task Transfer:** Train ordering on one task, evaluate on another; measure generalization.

3. **Ablation on Structure:** Compare ordering impact on (a) free-form text, (b) code, (c) structured data (JSON/XML).

4. **Scaling:** Does optimal ordering matter more or less as model size increases?

## Appendix: Mathematical Details

### A.1 Entropy Chain Rule and Ordering

By the chain rule of entropy:

$$H(\mathbf{x}) = \sum_{t=1}^{n} H(x_{\pi(t)} | \mathbf{x}_{\pi_{<t}})$$

This sum is invariant to ordering (always equals $H(\mathbf{x})$), but the *individual terms* vary. For generation, we care about minimizing the maximum or average term, not the sum.

### A.2 Submodularity of Entropy

Let $f(S) = H(\mathbf{x}_S)$ for $S \subseteq \{1, \ldots, n\}$.

Entropy is submodular:
$$f(S \cup \{i\}) - f(S) \geq f(T \cup \{i\}) - f(T) \quad \forall S \subseteq T$$

This property enables greedy approximation guarantees.

### A.3 Connection to Active Learning

The ordering problem is analogous to active learning:
- Active learning: which example to label next?
- Ordering: which token to generate next?

Both seek to maximize information gain per step.
